# perch v0.4.0

The release that makes perch answerable to the person on the other end of the
mailbox, rather than only to its operator. Replies now come back in the
sender's language, a failed run says something a human can act on instead of
leaking a Go error, and the agent can be given a standing role — a support
desk, a triager — that outlives any single email.

Upgrading is a drop-in: every new knob is opt-in and defaults to today's
behaviour. Nothing in `perch.yaml` needs to change.

## What the sender sees

**Replies mirror the sender's language.** A Chinese email got an English
answer, because nothing in the prompt asked otherwise and the framing around
the task (`Hi <name>,` / `Best,`) is itself English. `LANGUAGE` is now a hard
contract sent on every email — not just cold ones, because the answer can
change between turns of one thread. The greeting protocol learned 您好/你好,
and so did the scanner that decides where a reply starts: without that half,
an unrecognised greeting ships the agent's raw stdout, tool narration and all.

**A failed agent run no longer punishes the sender.** `nanopi failed: exec:
"nanopi": executable file not found in $PATH; stderr:` was mailed verbatim to a
customer filing a complaint. That is useless to them and leaks binary names,
paths and stderr. They now get a short out-of-office notice; the operator still
gets the real error at ERROR. A run that produces nothing usable twice asks for
a rephrase instead. perch writes both bodies itself, so it picks their language
too — including the long-task acknowledgement, which used to be Chinese
unconditionally.

**`回复：` is recognised as a reply prefix.** The check was ASCII-only, so a
thread opened by a Chinese client came back as `Re: 回复：…`, their client made
that `回复：Re: 回复：…`, and the subject grew a prefix pair per round.

## New: a standing role for the agent

`ai_agent.append_system_prompt` layers text onto the **agent's own** system
prompt on every run — the per-email prompt is about one message; this is about
who the agent is.

```yaml
ai_agent:
  append_system_prompt: /root/perch/helpdesk.md   # a path...
  # append_system_prompt: |                       # ...or inline text
  #   You are the support desk. Task definitions live in ./tasks/.
```

- **Text-or-path**, the same rule pi's flag follows. A file is **re-read on
  every email**, so editing the role takes effect on the next message with no
  restart; a failed re-read falls back to the last good content.
- **Support is probed, not tabled.** perch asks `<agent> --help` once at
  startup and passes the flag only if it appears — so it lights up on its own
  when an agent grows the flag, and an agent without it gets a WARN instead of
  a dead mailbox.
- **Sent on every run, resumes included.** nanopi rebuilds its system prompt
  from the current command line on resume, so omitting it on a reply would run
  that turn with no role at all.

`helpdesk.md.example` and `tasks.example/` are a fill-in-the-blanks support
desk: read task definitions from `tasks/`, ask for missing information instead
of guessing, invent no policy or prices, keep internals out of replies.

> Keep your copy **outside** the agent's workdir. Inside it, the SAFETY
> PROTOCOL treats the file as freely writable and the agent can rewrite its own
> instructions.

## New: an on-email script hook

`hooks.on_email` runs a script for every email perch accepts, before the agent:

```
<script> <email_id> <subject> <body> <sender> <new_thread|reply_thread>
```

An observer, never a gate — a missing script, a non-zero exit or a run past
`hooks.timeout` is logged and the email is handled anyway. It fires past
`allow_from` and the loop guards, so it only ever sees trusted senders.
`scripts/hooks/lark_bitable.py` is a working example (stdlib only) that appends
one row per email to a Lark Bitable, with an on-disk token cache so most emails
cost one HTTP call instead of two.

## Fixes

- **CI has been failing on every push since 2026-08-11** — `internal/setup`
  killed after ~99s. The wizard's "pick another agent" loop could not terminate
  when no agent binary was on PATH, which is true of every CI runner and of no
  developer machine. It also means a first-run wizard on a fresh box could spin.
- **A failed first run no longer poisons its thread.** The session id is minted
  and persisted before the agent runs, so a run that died left an id naming a
  session that never existed; the next email in that thread paid a doomed
  resume before recovering. It is now dropped when nothing confirmed it — while
  a session that *has* taken a turn survives a later failure.
- **Agent stderr is logged on success too.** A tool call that fails mid-run
  still exits 0, and the detail was being discarded.

## Operational notes

- `mailtest.yaml` is now `mailtest.yaml.example`; copy it (your copy, and
  `perch.yaml`, are gitignored).
- `make test-hooks` runs the example hook's own tests. CI stays Go-only.
- Startup logs say which system prompt was loaded and how, `system_prompt_bytes`
  appears per email, and an edited role file announces itself when it changes.

## Security

`allow_from` remains the whole trust boundary, and it is worth re-reading
before this release goes near a real mailbox: with `s".*"` any stranger can
reach an agent that has read access to the whole host. The new hook and the
standing role both sit *behind* that gate, but neither narrows it.

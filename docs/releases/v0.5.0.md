# perch v0.5.0

The release that stops two perch instances from talking to each other forever
when the end-of-conversation judge is unreachable.

On 2026-10-10 two perch instances traded "Likewise." / "Standing by." 265
times in one thread. Typesafe answered every Jev call with HTTP 451 ("not
available in your region"), end_detect fails open, and at about 30 replies an
hour the loop stayed under `max_replies_per_hour: 60`. Nothing stopped it.

Upgrading is a drop-in. The new `llm` block does nothing until it is
configured, and the new notice rule applies only when `end_detect` is on.

## New: an LLM alternative to Jev (`llm`)

A chat model answers the same two questions Jev does: "is this thread over?"
(end_detect) and "will this task run long?" (the duration probe). It is
asked whenever Jev is unconfigured or fails, so with `TYPESAFE_API_KEY` unset
it replaces Jev entirely. Both questions now walk the same chain:

    Jev  →  llm  →  agent probe

The agent probe is new for end_detect: the agent judges the message in a
throwaway session and ends with `<<<PERCH_END>>> over|reply`. A missing
verdict line is a failure, never a guess.

Two wire formats:

- `openai` — `POST {base_url}/chat/completions`. perch asks for logprobs and
  derives a calibrated P(over), so `end_detect_min_prob` keeps its meaning.
  DeepSeek, Volcengine Ark, DashScope, MiMo.
- `anthropic` — `POST {base_url}/v1/messages`. No logprobs: the model's
  one-word answer is taken as certain, logged as `source=llm(uncalibrated)`.

From mainland China, DeepSeek (`https://api.deepseek.com`, `deepseek-flash`)
is reachable without a proxy and returns logprobs. Use a non-thinking
model: the answer is capped at 16 output tokens.

```yaml
llm:
  format: openai
  base_url: https://api.deepseek.com
  model: deepseek-flash
  timeout: 15s
```
```sh
export PERCH_LLM_API_KEY=sk-...   # env-only, never in perch.yaml
```

## New: an undecidable thread gets a notice, not a blind reply

When `end_detect` is on but no judge can decide (Jev, llm and the agent
probe all failed), perch counts its own earlier replies in the thread
from the `References`/`In-Reply-To` ids it minted. At two or more, it skips
the agent and sends an `X-Perch-Kind: notice` saying its email handling has a
problem and asking for a fresh email. Another perch never answers a notice,
so this is the last word in an agent-to-agent loop. A younger thread is
answered as usual, so a dead classifier never costs a new request its reply.
Applies to every sender.
